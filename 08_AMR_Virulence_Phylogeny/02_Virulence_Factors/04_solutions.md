# پاسخ تشریحی: عامل‌های بیماری‌زایی

خروجی تمرین‌های ۱، ۲، ۴ و ۵ واقعی‌اند (AMRFinderPlus 4.2.7 / پایگاه 2026-08-07.1؛ BLAST+ 2.17.0؛ VFDB setA از مخزن ABRicate، commit `e2064df`؛ اجرا در 2026-10-24). تمرین ۶ را اجرا نکرده‌ایم. تمرین ۷ روی جدول فرضی است.

## پاسخ ۱: بی `--plus`

<div dir="ltr">

```bash
amrfinder -n genomes/isoD.fna --organism Escherichia --name isoD -o isoD.noplus.tsv
tail -n +2 isoD.noplus.tsv | wc -l
amrfinder -n genomes/isoE.fna --organism Escherichia --name isoE -o isoE.noplus.tsv
tail -n +2 isoE.noplus.tsv | cut -f7,9
```

</div>

**خروجی واقعی:**

<div dir="ltr">

```
0
blaCTX-M-15	core
```

</div>

- (الف) **صفر سطر.** حتی سطر stxtyper هم نیست؛ همه‌ی یافته‌های بیماری‌زایی isoD در گروه plus‌اند.
- (ب) تنها `blaCTX-M-15` (core) ماند؛ چهار ژن بیماری‌زایی گم شدند.
- (ج) یک پاسخ نمونه: «گزارش "هیچ ژنی پیدا نشد" برای isoD با گزینه‌ای گرفته شده که ژن‌های بیماری‌زایی را اصلاً نمی‌جوید؛ همین ایزوله با `--plus` ژن سم شیگا 2a و اینتیمین دارد، یعنی نشانگرهای STEC با خطر HUS.»

## پاسخ ۲: خواندن stxtyper

<div dir="ltr">

```bash
awk -F'\t' '$11=="STX_TYPE" {print $4, $5, $7, $13, $14}' isoD.amr.tsv
```

</div>

**خروجی واقعی:**

<div dir="ltr">

```
2001 3238 stx2a_operon STX2A COMPLETE
```

</div>

- (الف) آغاز ۲۰۰۱، پایان ۳۲۳۸، نماد `stx2a_operon`، زیرنوع `STX2A`، ‏Method `COMPLETE`.
- (ب) ‏3238 − 2001 + 1 = **۱۲۳۸** باز؛ سه باز کمتر از ۱۲۴۱. این سه باز **کدون پایان** `stxB2` است که AMRFinderPlus در مختصات نمی‌آورد (همان رفتار ماژول ۰۱ برای CTX-M-15).
- (ج) **نه.** به گفته‌ی README ‏stxtyper، اپرون‌های `PARTIAL_CONTIG_END` (و `PARTIAL`، `INTERNAL_STOP`، `FRAMESHIFT`، `EXTENDED`) «احتمالاً ناقص یا ناکارا» شمرده می‌شوند و زیرنوع نمی‌گیرند؛ تنها تا سطح نوع (stx2) گزارش می‌شوند. برای زیرنوع، اسمبلی بهتر (long-read) یا PCR زیرنوع لازم است.

## پاسخ ۳: پاتوتیپ هر ایزوله

| ایزوله | پاتوتیپ احتمالی | مقاومت core | جمله‌ی گزارشی |
| :--- | :--- | :--- | :--- |
| ‏isoA | بی نشانگر بیماری‌زایی ویژه | ‏`blaCTX-M-15`، `gyrA_S83L` | «مقاوم به سفالوسپورین نسل سوم و کینولون (پیش‌بینی)؛ نشانگر پاتوتیپ پیدا نشد.» |
| ‏isoB | بی نشانگر | ‏`blaNDM-1`، `parC_S80I`، `tet(A)` ناقص | «کارباپنماز NDM-1؛ نشانگر پاتوتیپ پیدا نشد.» |
| ‏isoC | همزیست (K-12) | هیچ | «نه مقاومت core، نه نشانگر پاتوتیپ.» |
| ‏isoD | ‏**EHEC / STEC** (`stx2a` + `eae` + `ehxA`) | هیچ | «نشانگرهای EHEC با زیرنوع stx2a (خطر HUS)؛ مقاومت core ندارد.» |
| ‏isoE | ‏**ExPEC / UPEC** (`papC`، `sat`، `cnf1`، `iutA`) | ‏`blaCTX-M-15` | «نشانگرهای ExPEC همراه با ESBL: هم‌گرایی بیماری‌زایی و مقاومت.» |

**اشتباه رایج:** نوشتن «isoA بیماری‌زا نیست». ما تنها می‌دانیم **نشانگرهای پایگاه** پیدا نشدند؛ ‏*E. coli* مقاوم بی این نشانگرها هم می‌تواند در بیمار با ایمنی ضعیف عفونت بدهد.

## پاسخ ۴: آستانه‌ی پوشش در VFDB

<div dir="ltr">

```bash
for i in isoC isoE; do
  awk -F'\t' '$5/$6 >= 0.6' $i.vfdb.tsv | awk -F'~~~' '{print $2}' | sort -u > $i.vf60.txt
  echo "$i $(wc -l < $i.vf60.txt)"
done
cat isoE.vf.txt isoE.vf.txt isoE.vf60.txt | sort | uniq -u
```

</div>

**خروجی واقعی:**

<div dir="ltr">

```
isoC 65
isoE 69
papC
```

</div>

- (الف) ‏isoC همان **۶۵**؛ ‏isoE از ۶۸ به **۶۹**.
- (ب) ‏**papC** (تکه‌ی ۱۵۴۹ بازی، ۶۲٪، از آستانه‌ی ۶۰٪ گذشت).
- (ج) جمع ساده: ‏1549 + 883 + 95 = 2527؛ ‏2527 / 2511 = **۱۰۰٫۶٪**. بیش از ۱۰۰٪ است چون تکه‌ها روی contig **هم‌پوشانی** دارند: ‏2001–3549، ‏3542–3636 و 3629–4511؛ یعنی ۸ باز میان تکه‌ی ۱ و ۲، و ۸ باز میان ۲ و ۳، دو بار شمرده شده‌اند. پوشش درست، **اجتماع** بازه‌هاست: ‏2001 تا 4511 = ‏۲۵۱۱ باز = **۱۰۰٪**. ژن کامل است و تنها هم‌ردیفی BLAST تکه‌تکه شده بود.

## پاسخ ۶ (اختیاری): ABRicate

این تمرین را اجرا نکرده‌ایم؛ آنچه باید بسنجید:

<div dir="ltr">

```bash
conda activate abricate
abricate --db vfdb genomes/isoC.fna | tail -n +2 | cut -f6 | sort -u | wc -l
abricate --db vfdb genomes/isoE.fna | grep -w papC
abricate --db ecoli_vf genomes/isoC.fna genomes/isoE.fna > ecoli_vf.tsv
```

</div>

- (الف) شمار باید **نزدیک** به ۶۵ باشد. اگر کمی فرق داشت، دلیلش شاید نسخه‌ی پایگاه (`abricate --list`، ستون DATE) یا شیوه‌ی شمردن تکه‌هاست.
- (ب) ‏ABRicate هم با `--mincov 80` کار می‌کند. اینکه papC را می‌آورد یا نه به این بستگی دارد که تکه‌های هم‌ردیفی را چگونه یکی کند؛ README خودش می‌گوید محاسبه‌ی پوشش کاستی دارد. نتیجه را با پاسخ ۴ بسنجید و ستون `COVERAGE_MAP` را ببینید.
- (ج) ‏`ecoli_vf` ویژه‌ی *E. coli* است؛ برای جدا کردن ژن‌های ExPEC از ژن‌های عمومی بهتر است. ولی باز هم باید با یک کنترل (isoC) سنجید.

## پاسخ ۷: امتیازهای Kleborate (فرضی)

| ایزوله | امتیاز بیماری‌زایی | چرا | امتیاز مقاومت | چرا |
| :--- | :---: | :--- | :---: | :--- |
| ‏Kp1 | 1 | تنها ybt | 0 | ‏SHV-11 کروموزومی ESBL نیست |
| ‏Kp2 | 5 | ‏ybt + clb + iuc | 1 | ‏ESBL بی کارباپنماز |
| ‏Kp3 | 1 | تنها ybt | 3 | کارباپنماز KPC + مقاومت به کولیستین (mgrB) |
| ‏Kp4 | 3 | ‏iuc بی ybt و clb | 2 | کارباپنماز بی مقاومت به کولیستین |

- (ب) ‏**Kp4**: آئروباکتین (iuc، نشانگر hvKp) + کارباپنماز. ‏Kp2 بیماری‌زایی بالا دارد ولی کارباپنماز ندارد؛ Kp3 مقاومت بسیار بالا دارد ولی بیماری‌زایی پایین.
- (ج) به گفته‌ی مستند Kleborate، `iro` و `rmpADC` **در امتیاز شمرده نمی‌شوند**؛ امتیاز تنها بر پایه‌ی ybt، clb و iuc است. ‏Kp4 تنها iuc را از این سه دارد، پس ۳.

## پاسخ ۸: فکری — ژن ناقص در نقشه

- (الف) خطی که `grid$present` را می‌سازد، تنها «هست/نیست» (0/1) می‌دهد. می‌توان یک مقدار سوم ساخت: اگر ستون `Method` با `PARTIAL` آغاز شود، به جای 1 مقدار «partial» بگذارد، و در `scale_fill_manual` برای آن رنگ سوم (برای نمونه نارنجی) تعریف کرد.
- (ب) **نشانه‌دار**، نه حذف. حذف، این اطلاعات را پنهان می‌کند که بخشی از ژن هست (شاید باقی‌مانده‌ی یک ترانسپوزون، یا ژنی که میان دو contig بریده شده). خواننده باید ببیند و خودش تصمیم بگیرد؛ گزارش باید روشن بگوید رنگ سوم یعنی «ناقص، اثر نامعلوم».
