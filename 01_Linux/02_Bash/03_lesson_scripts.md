# درس ۳: متغیر، حلقه و اسکریپت

**بخش:** `01_Linux` · **ماژول:** `02_Bash` · **پیش‌نیاز:** [درس ۲](02_lesson_text_tools.md) · **زمان:** حدود ۴۵ دقیقه · **ابزار:** bash 5 · **آخرین اجرا:** 2026-10-19

---

## در یک نگاه

**در پایان این درس می‌توانید:**
1. مقداری را در یک متغیر بگذارید و خروجی یک دستور را در متغیر بریزید.
2. با حلقه‌ی `for` یک کار را روی چندین فایل تکرار کنید.
3. دستورها را در یک فایل اسکریپت بنویسید و با ورودی اجرا کنید.
4. با `set -euo pipefail` اسکریپت را در برابر خطاهای بی‌صدا ایمن کنید.
5. کار طولانی را طوری اجرا کنید که با بستن ترمینال قطع نشود.

---

## ۱. داستان: کاری که باید ۱۰۰ بار تکرار شود

در درس ۲ شمار ریدها و میانگین طولشان را برای **یک** فایل FASTQ گرفتیم. پروژه‌ی واقعی ده‌ها یا صدها نمونه دارد. نوشتن همان دستور ۱۰۰ بار، با عوض کردن دستی نام فایل، هم کند است و هم پر از خطا: یک نام اشتباه، یک نمونه‌ی فراموش‌شده.

راه‌حل دو چیز است:
- **حلقه:** «این کار را برای هر فایل تکرار کن».
- **اسکریپت:** دستورها را یک بار در فایلی بنویس و هر بار آن فایل را اجرا کن. این همان «دستور پخت دقیق» بخش ۰۰ است.

---

## ۲. متغیر: نامی برای یک مقدار

<div dir="ltr">

```bash
name="minigut"
echo "sample: $name"
```

</div>

<div dir="ltr">

```text
sample: minigut
```

</div>

- `name="minigut"` مقدار را در متغیر `name` می‌گذارد. **دو سوی `=` فاصله نگذارید**؛ `name = "minigut"` خطا می‌دهد.
- `$name` جای مقدار را می‌گیرد.
- `echo` متن را چاپ می‌کند.

### ریختن خروجی یک دستور در متغیر
`$( … )` دستور درونش را اجرا می‌کند و خروجی را به جای خودش می‌گذارد:

<div dir="ltr">

```bash
R=fastq
n=$(zcat $R/minigut_R1.fastq.gz | wc -l)
echo $n
echo $((n/4))
```

</div>

<div dir="ltr">

```text
200000
50000
```

</div>

`$(( … ))` برای حساب با عدد درست است: ۲۰۰٬۰۰۰ ÷ ۴ = ۵۰٬۰۰۰ رید.

## ۳. حلقه‌ی `for`: یک کار برای هر فایل

ساختار حلقه:

<div dir="ltr">

```text
for f in فهرست; do
    کاری با "$f"
done
```

</div>

در هر دور، `f` یکی از چیزهای فهرست می‌شود. برای ساختن فهرست فایل‌ها از `*` به کار می‌بریم که یعنی «هر چیزی»:

<div dir="ltr">

```bash
for f in $R/*_R1.fastq.gz; do
  echo "$f"
done
```

</div>

<div dir="ltr">

```text
fastq/minigut_R1.fastq.gz
fastq/minigut_sample2_R1.fastq.gz
```

</div>

`*_R1.fastq.gz` یعنی «هر فایلی که نامش به `_R1.fastq.gz` پایان می‌یابد». دو فایل یافت شد، پس حلقه دو بار اجرا شد.

### گرفتن نام نمونه از نام فایل
`basename` نشانی پوشه را برمی‌دارد و اگر پسوندی به آن بدهید، آن را هم برمی‌دارد:

<div dir="ltr">

```bash
for f in $R/*_R1.fastq.gz; do
  basename "$f" _R1.fastq.gz
done
```

</div>

<div dir="ltr">

```text
minigut
minigut_sample2
```

</div>

### کنار هم گذاشتن همه: جدول شمار ریدها

<div dir="ltr">

```bash
for f in $R/*_R1.fastq.gz; do
  s=$(basename "$f" _R1.fastq.gz)
  n=$(zcat "$f" | awk 'END{print NR/4}')
  printf "%s\t%s\n" "$s" "$n"
done
```

</div>

<div dir="ltr">

```text
minigut	50000
minigut_sample2	24993
```

</div>

**این حلقه گام‌به‌گام:** برای هر فایل، نام نمونه را در `s` و شمار ریدها را در `n` بگذار، سپس هر دو را با یک Tab میانشان (`\t`) و پایان خط (`\n`) چاپ کن. اگر ۱۰۰ فایل داشتید، همین چند خط ۱۰۰ ردیف می‌ساخت.

**همیشه متغیرها را در نقل‌قول بنویسید** (`"$f"`). اگر نام فایلی فاصله داشته باشد (`my sample.fastq.gz`)، بی نقل‌قول به دو تکه شکسته می‌شود و دستور خطا می‌دهد.

<details>
<summary>✋ <b>امتحان کن:</b> حلقه‌ای بنویسید که برای هر فایل <code>*_R1.fastq.gz</code> تنها نخستین خط (نام نخستین رید) را چاپ کند.</summary>

<div dir="ltr">

```bash
for f in $R/*_R1.fastq.gz; do
  zcat "$f" | head -n 1
done
```

</div>

پاسخ: `@NC_006347.1_0/1` برای `minigut` و `@CP009257.1_0_0/1` برای `minigut_sample2`. نام رید در این داده‌ی شبیه‌سازی‌شده، ژنوم سرچشمه را می‌گوید.
</details>

## ۴. اسکریپت: دستورها در یک فایل

اسکریپت یک فایل متنی است که دستورها را پشت سر هم دارد. این اسکریپت آماده‌ی ماژول است: [scripts/count_reads.sh](../99_scripts_data/02_Bash/scripts/count_reads.sh)

<div dir="ltr">

```bash
#!/usr/bin/env bash
# Count reads and mean read length in one or more FASTQ(.gz) files.
# Usage: bash count_reads.sh file1.fastq.gz [file2.fastq.gz ...]
set -euo pipefail

if [ $# -eq 0 ]; then
  echo "Usage: bash count_reads.sh file1.fastq.gz [file2 ...]" >&2
  exit 1
fi

printf "sample\treads\tmean_length\n"
for f in "$@"; do
  if [ ! -s "$f" ]; then
    echo "Error: file '$f' not found or empty" >&2
    exit 1
  fi
  name=$(basename "$f" .fastq.gz)
  zcat "$f" | awk -v s="$name" 'NR%4==2 {n++; L+=length($0)} END{printf "%s\t%d\t%.1f\n", s, n, L/n}'
done
```

</div>

**خط‌به‌خط:**
- `#!/usr/bin/env bash`: خط یکم می‌گوید این فایل را با Bash اجرا کن.
- خط‌هایی که با `#` آغاز می‌شوند **یادداشت**‌اند و اجرا نمی‌شوند. بنویسید اسکریپت چه می‌کند و چطور اجرا می‌شود؛ شش ماه بعد خودتان سپاسگزار خواهید بود.
- `set -euo pipefail`: سپر ایمنی (بخش ۵).
- `$#` شمار ورودی‌هاست. `if [ $# -eq 0 ]` یعنی «اگر هیچ ورودی ندادند»، پیام راهنما را چاپ کن و با کد خطا (`exit 1`) بیرون برو.
- `"$@"` همه‌ی ورودی‌هایی است که به اسکریپت داده‌اید. حلقه روی آن‌ها می‌گردد.
- `[ ! -s "$f" ]` یعنی «اگر فایل نیست یا خالی است».
- `>&2` پیام را در **خروجی خطا** (stderr) می‌نویسد، نه در خروجی اصلی؛ پس اگر خروجی را در فایلی بریزید، پیام خطا در آن نمی‌رود.
- `awk -v s="$name"` مقدار متغیر Bash را به `awk` می‌دهد.

### اجرای اسکریپت

<div dir="ltr">

```bash
bash ../scripts/count_reads.sh $R/*_R1.fastq.gz
```

</div>

<div dir="ltr">

```text
sample	reads	mean_length
minigut_R1	50000	126.0
minigut_sample2_R1	24993	151.0
```

</div>

**این خروجی یعنی:** نمونه‌ی `minigut` ۵۰٬۰۰۰ رید با میانگین طول ۱۲۶ دارد (همان عدد درس ۲)، و `minigut_sample2` ۲۴٬۹۹۳ رید با طول ۱۵۱.

و اگر نام فایل را اشتباه بنویسید:

<div dir="ltr">

```bash
bash ../scripts/count_reads.sh nofile.fastq.gz
```

</div>

<div dir="ltr">

```text
sample	reads	mean_length
Error: file 'nofile.fastq.gz' not found or empty
```

</div>

اسکریپت با پیامی روشن می‌ایستد. بی آن بررسی، `zcat` خطا می‌داد ولی `awk` باز هم اجرا می‌شد و با خطای گیج‌کننده‌ی «division by zero» (تقسیم بر صفر) می‌ایستاد. یعنی پیام خطا ربطی به اشتباه واقعی (نام نادرست فایل) نداشت.

### نوشتن اسکریپت خودتان
یک ویرایشگر ساده‌ی ترمینال `nano` است:

<div dir="ltr">

```bash
nano my_script.sh      # بنویسید؛ Ctrl+O ذخیره، Ctrl+X بیرون
bash my_script.sh      # اجرا
```

</div>

VS Code و ویرایشگرهای دیگر هم برای نوشتن اسکریپت خوب‌اند. تنها Word یا برنامه‌های همانند را به کار نبرید، چون نویسه‌های پنهان به متن می‌افزایند.

## ۵. سپر ایمنی: `set -euo pipefail`

هر اسکریپت تحلیلی را با این خط آغاز کنید. سه کار می‌کند:

| بخش | بی آن | با آن |
| :--- | :--- | :--- |
| `-e` | اگر دستوری خطا بدهد، اسکریپت **بی‌صدا ادامه** می‌دهد و خروجی ناقص می‌سازد | اسکریپت با نخستین خطا **می‌ایستد** |
| `-u` | متغیری که تعریف نشده (برای نمونه از غلط تایپی) **رشته‌ی خالی** می‌شود | به کار بردن متغیر تعریف‌نشده **خطا** است |
| `-o pipefail` | در لوله تنها خطای **آخرین** دستور دیده می‌شود | خطای **هر** دستوری در لوله دیده می‌شود |

**نمونه‌ی خطرناک بی `-u`:**

<div dir="ltr">

```bash
rm -rf "$OUTDIR/"      # اگر OUTDIR را تعریف نکرده باشید، این می‌شود: rm -rf "/"
```

</div>

با `-u` این دستور اجرا نمی‌شود و اسکریپت با خطای «unbound variable» (متغیر تعریف‌نشده) می‌ایستد.

## ۶. کارهای طولانی

برخی ابزارهای بیوانفورماتیک ساعت‌ها کار می‌کنند. اگر ترمینال را ببندید یا اینترنت قطع شود، کار هم قطع می‌شود. دو راه:

<div dir="ltr">

```bash
nohup bash long_job.sh > job.log 2>&1 &     # در پس‌زمینه؛ با بستن ترمینال قطع نمی‌شود
```

</div>

- `nohup` یعنی «با بسته شدن ترمینال کار را نکش».
- `> job.log 2>&1` خروجی و پیام‌های خطا را با هم در `job.log` می‌ریزد.
- `&` در پایان یعنی «در پس‌زمینه اجرا کن و ترمینال را آزاد بگذار».

راه دوم **tmux** است: یک «نشست» پایدار که می‌توانید از آن جدا شوید و بعداً برگردید:

<div dir="ltr">

```bash
tmux new -s analysis     # نشست تازه
# … کار را اجرا کنید، سپس Ctrl+b و پس از آن d برای جدا شدن
tmux attach -t analysis  # بازگشت به نشست
```

</div>

روی سرورهای مشترک دانشگاه، کارهای سنگین را با سامانه‌ی صف (مانند SLURM، بخش ۱۰) اجرا کنید، نه مستقیم.

## ۷. سه اشتباه رایج

| اشتباه | چرا مشکل است | به جایش چه کنیم |
| :--- | :--- | :--- |
| `name = "x"` (فاصله دو سوی `=`) | Bash گمان می‌کند `name` یک دستور است | `name="x"` |
| متغیر بی نقل‌قول (`$f`) | نام‌های دارای فاصله می‌شکنند | `"$f"` |
| اسکریپت بی `set -euo pipefail` | خطا بی‌صدا نادیده گرفته می‌شود و خروجی ناقص می‌ماند | همیشه در خط دوم اسکریپت |

---

## ۸. جمع‌بندی

- **متغیر:** `name="x"` و `$name`؛ خروجی دستور با `$( … )`.
- **حلقه:** `for f in …; do … done` یک کار را برای هر فایل تکرار می‌کند؛ `basename` نام نمونه را می‌دهد.
- **اسکریپت:** دستورها در یک فایل، با یادداشت، با بررسی ورودی‌ها، و با `set -euo pipefail`.
- **کار طولانی:** `nohup … &` یا `tmux`.

---

<details>
<summary>📘 <b>برای کنجکاوها (اختیاری):</b> چرا <code>zcat file | head</code> با <code>pipefail</code> گاهی خطای 141 می‌دهد؟</summary>

`head` پس از خواندن چند خط، لوله را می‌بندد. `zcat` که هنوز می‌خواهد بنویسد، پیام «لوله بسته شد» (SIGPIPE) می‌گیرد و با کد ۱۴۱ می‌ایستد. بی `pipefail` این دیده نمی‌شود، ولی با `pipefail` کل لوله «خطا» حساب می‌شود و `-e` اسکریپت را می‌ایستاند، در حالی که هیچ اشتباهی رخ نداده است. در اسکریپت‌های این دوره، برای همان یک خط `set +o pipefail` گذاشته‌ایم (نمونه: [run_profile.sh](../../06_Metagenomics/03_Taxonomic_Functional_Profiling/scripts/run_profile.sh)). در کار روزمره در ترمینال، این مشکلی نیست، چون `pipefail` روشن نیست.
</details>

## واژه‌نامه‌ی این درس

| اصطلاح | معنی |
| :--- | :--- |
| متغیر | نامی برای یک مقدار (`name="x"`، سپس `$name`) |
| `$( … )` | اجرای یک دستور و گذاشتن خروجی‌اش به جای خودش |
| حلقه‌ی `for` | تکرار یک کار برای هر چیز در یک فهرست |
| `*` (wildcard) | «هر چیزی» در نام فایل‌ها: `*_R1.fastq.gz` |
| اسکریپت | فایل متنی از دستورها که با `bash file.sh` اجرا می‌شود |
| `$#` / `"$@"` | شمار ورودی‌های اسکریپت / همه‌ی ورودی‌ها |
| stderr (`>&2`) | خروجی ویژه‌ی پیام‌های خطا، جدا از خروجی اصلی |
| `set -euo pipefail` | سپر ایمنی: ایستادن با خطا، متغیر تعریف‌نشده، و خطای درون لوله |
