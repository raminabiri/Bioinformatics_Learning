# پاسخ تشریحی: حساب کردن روی ستون‌ها با awk

> دستورها در 2026-10-20 در پوشه‌ی `01_Linux/99_scripts_data/data` با mawk 1.3.4 (awk پیش‌فرض Ubuntu 24.04) و GNU awk 5.4.1 اجرا شدند؛ خروجی هر دو یکی است.

---

## تمرین ۱: مختصات CDSها

<div dir="ltr">

```bash
awk -F'\t' '$3=="CDS" {print $4, $5, $7}' small.gff
```

</div>

<div dir="ltr">

```text
190 255 +
337 2799 +
2801 3733 +
```

</div>

سه CDS، همه روی رشته‌ی مثبت، با همان مختصات ژن‌هایشان. (خط هشتم `small.gff` ژن *thrC* است و CDS آن در خط نهم فایل اصلی است، پس در `small.gff` نیست.)

---

## تمرین ۲: ژن‌های بلند

<div dir="ltr">

```bash
awk -F'\t' '$3=="gene" && $5-$4+1 > 4500 {print $4, $5, $7, $5-$4+1}' ecoli_k12.gff
```

</div>

<div dir="ltr">

```text
1729087 1733703 + 4617
2044995 2052014 + 7020
2647326 2652287 - 4962
2778146 2782726 - 4581
3114550 3119112 - 4563
```

</div>

**پنج ژن.** بلندترین ۷٬۰۲۰ نوکلئوتید است (ژن *yeeJ*؛ کادر «برای کنجکاوها» در درس).

**اشتباه رایج:** نوشتن `$5-$4 > 4500` بی `+1`. این‌جا پاسخ همان است، ولی برای ژنی با طول دقیقاً ۴٬۵۰۱، یکی جا می‌افتد.

## تمرین ۳: میانگین طول CDSها

<div dir="ltr">

```bash
awk -F'\t' '$3=="CDS" {l=$5-$4+1; s+=l; n++} END{printf "n=%d mean=%.1f\n", n, s/n}' ecoli_k12.gff
```

</div>

<div dir="ltr">

```text
n=4340 mean=927.9
```

</div>

میانگین CDSها (۹۲۷٫۹) از میانگین ژن‌ها (۸۹۷٫۴) بیشتر است، چون «ژن»ها ژن‌های RNA (tRNA با نزدیک به ۷۸ نوکلئوتید، ncRNAها و…) را هم دارند. این ژن‌ها بسیار کوتاه‌اند و میانگین را پایین می‌آورند. CDSها تنها بخش‌های پروتئین‌سازند.

## تمرین ۵: ژن‌های RNA

<div dir="ltr">

```bash
awk -F'\t' '$3=="gene" && $9 ~ /gene_biotype=tRNA/ {n++} END{print n}' ecoli_k12.gff
awk -F'\t' '$3=="gene" && $9 ~ /gene_biotype=rRNA/ {n++} END{print n}' ecoli_k12.gff
```

</div>

<div dir="ltr">

```text
86
22
```

</div>

1. **۸۶ ژن tRNA.**
2. **۲۲ ژن rRNA.**
3. **۷ اپرون**: ۷ × ۳ = ۲۱، به‌اضافه‌ی یک ژن 5S اضافه = ۲۲.

**چرا `$3=="gene"` لازم است؟** نوع `tRNA` در ستون ۳ هم هست (خط‌های جداگانه‌ای برای خود tRNA). شرط روی خط‌های `gene` می‌گذارد هر ژن تنها یک بار شمرده شود.

## تمرین ۶: ژن gyrA کجاست؟

<div dir="ltr">

```bash
awk -F'\t' '$3=="gene" && $9 ~ /Name=gyrA;/ {print $4, $5, $7, $5-$4+1}' ecoli_k12.gff
```

</div>

<div dir="ltr">

```text
2336793 2339420 - 2628
```

</div>

آغاز **۲٬۳۳۶٬۷۹۳**، پایان **۲٬۳۳۹٬۴۲۰**، رشته‌ی **منفی**، طول **۲٬۶۲۸**: همان چیزی که در NCBI Gene دیده می‌شود. ۲٬۶۲۸ ÷ ۳ = ۸۷۶ کدون = ۸۷۵ اسیدآمینه + یک کدون پایان.

**نکته:** برای ژن روی رشته‌ی منفی، **آغاز زیستی** (کدون ATG) جای بزرگ‌تر، یعنی ۲٬۳۳۹٬۴۲۰، است. GFF همیشه عدد کوچک‌تر را در ستون ۴ و جهت را در ستون ۷ می‌نویسد.

**اشتباه رایج:** نوشتن `/Name=gyrA/` بی `;`. این‌جا پاسخ همان است، ولی در ژنوم‌های دیگر ممکن است ژنی مانند `gyrAB` هم پیدا شود.

---

## تمرین ۷: ژن‌های رشته‌ی منفی در یک مگاباز نخست

<div dir="ltr">

```bash
awk -F'\t' '$3=="gene" && $7=="-" && $4<=1000000' ecoli_k12.gff | wc -l
awk -F'\t' '$3=="gene" && $7=="-" && $5<=1000000' ecoli_k12.gff | wc -l
```

</div>

<div dir="ltr">

```text
437
437
```

</div>

1. **۴۳۷ ژن.**
2. برای «کاملاً درون»، **پایان** هم باید درون بازه باشد: `$5<=1000000`. این‌جا پاسخ همان ۴۳۷ است، چون هیچ ژنِ رشته‌ی منفی‌ای از مرز یک مگاباز نمی‌گذرد. ولی در گزارش همیشه بنویسید تعریفتان چه بوده است.

---

## تمرین ۸: ریدها از کدام ژنوم‌ها آمده‌اند؟

<div dir="ltr">

```bash
zcat fastq/minigut_sample2_R1.fastq.gz | awk 'NR%4==1' \
  | grep -oE '^@[A-Z]+_?[0-9]+\.[0-9]+' | sort | uniq -c | sort -rn | head -n 3
grep -E 'CP009257.1|NC_002516.2|NC_004461.1' ground_truth.tsv
```

</div>

<div dir="ltr">

```text
  16154 @CP009257.1
   1178 @NC_002516.2
    965 @NC_004461.1
minigut_sample2	16154	CP009257.1	Acinetobacter baumannii strain AB030
minigut_sample2	1178	NC_002516.2	Pseudomonas aeruginosa PAO1
minigut_sample2	965	NC_004461.1	Staphylococcus epidermidis ATCC 12228
```

</div>

1. ‏*Acinetobacter baumannii* با **۱۶٬۱۵۴** رید، *Pseudomonas aeruginosa* با **۱٬۱۷۸**، و *Staphylococcus epidermidis* با **۹۶۵**.
2. شمارهای ما دقیقاً با جدول «پاسخ درست» شبیه‌سازی یکی است.

(`\` در پایان خط یکم یعنی «دستور در خط بعد ادامه دارد»؛ تنها برای خوانایی است.)

**اشتباه رایج:** `grep '^@'` روی کل FASTQ، به جای `awk 'NR%4==1'`. خط کیفیت هم ممکن است با `@` آغاز شود (در Phred+33، `@` یعنی کیفیت ۳۱)، پس شمارش خراب می‌شود.

</div>
