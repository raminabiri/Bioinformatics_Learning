# تمرین‌ها: Git و GitHub

> پیش از شروع، مخزن تمرینی درس را بسازید:
> ```bash
> cd 05_Reproducible_Work/01_Git_GitHub
> bash scripts/git_demo.sh ../01_Bash_Linux/data/ecoli_k12.gff ~/git_practice
> cd ~/git_practice/ecoli_project
> ```

---

## تمرین ۱ (تاریخچه): والدهای یک merge

1. `git log --oneline --graph --all` را اجرا کنید. hashها با درس یکسان‌اند؟ چرا؟
2. commit ادغام (merge) دو والد دارد. `HEAD~1`، `HEAD^2` و `HEAD~2` هر کدام به کدام commit اشاره می‌کنند؟
3. با `git diff --stat cc62ffa HEAD` بگویید از اولین commit تا الان چند فایل و چند خط تغییر کرده است.

---

## تمرین ۲ (.gitignore): چه چیزی وارد مخزن می‌شود؟

این فایل‌ها را بسازید: `results/table.tsv`، `data/raw/b.fastq.gz`، `notes.fastq.gz` و `scripts/plot.R`.
1. پیش‌بینی کنید کدام‌ها در `git status` ظاهر می‌شوند.
2. با `git check-ignore -v` نشان دهید هر فایل نادیده‌گرفته‌شده به خاطر **کدام خط** `.gitignore` است.
3. یک قانون اضافه کنید که فایل‌های `*.bam` و `*.bai` را هم در هر پوشه‌ای نادیده بگیرد.

## تمرین ۳ (کارآگاهی): چه کسی و کِی؟

1. با `git blame scripts/count_genes.sh` بگویید هر خط آخرین بار در کدام commit تغییر کرده است.
2. با `git log -p -- scripts/count_genes.sh` همه‌ی نسخه‌های خط سوم را به ترتیب زمانی فهرست کنید.
3. نسخه‌ی `31e9354` اسکریپت را **بدون تغییر پوشه‌ی کاری** روی GFF اجرا کنید.

---

## تمرین ۴ (conflict): تصمیم متفاوت

1. یک کپی تازه از مخزن تمرینی بسازید (دوباره `git_demo.sh` با پوشه‌ی دیگر). قبل از commit ادغام، می‌خواهیم **همه‌ی ژن‌ها** (نه فقط tRNA) را به تفکیک کروموزوم و رشته بشماریم. یعنی تغییر `main` را نگه داریم و تغییر branch را رد کنیم.
   راهنمایی: می‌توانید merge را از اسکریپت جدا کنید و خودتان اجرا کنید، یا روی مخزن تازه `git reset --hard HEAD~1` بزنید (فقط چون این مخزن تمرینی است) و دوباره `git merge add-trna` کنید. برای پذیرش یک طرف: `git checkout --ours <file>`.
2. خروجی اسکریپت حل‌شده روی GFF چیست؟
3. در یک پروژه‌ی واقعی، چه کسی باید چنین conflictی را حل کند و چرا Git نمی‌تواند خودکار تصمیم بگیرد؟

## تمرین ۵ (اشتباه خطرناک): رمز در مخزن

1. فایلی به نام `secret.txt` با محتوای `API_KEY=abc123` بسازید، commit کنید، بعد با `git rm --cached` و افزودن به `.gitignore` آن را «حذف» و commit کنید.
2. آیا رمز واقعاً از مخزن رفته است؟ با `git show` نشان دهید.
3. اگر این مخزن قبلاً روی GitHub عمومی push شده باشد، **اولین** کاری که باید بکنید چیست؟

## تمرین ۶ (چالشی): پروژه‌ی خودتان

پوشه‌ی `ecoli_project` تمرین ۱ ماژول 01/01 (یا هر پروژه‌ی واقعی خودتان) را به یک مخزن git تبدیل کنید:
- `.gitignore` مناسب (داده، نتایج قابل بازتولید، فایل‌های موقت)
- `README.md` کوتاه: هدف، نحوه‌ی اجرا، نحوه‌ی دریافت داده
- `environment.yml` (ماژول ۰۲)
- دست‌کم سه commit معنادار و یک tag
- (اختیاری) push به GitHub و ساخت یک Release
