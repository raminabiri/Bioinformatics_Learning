# 🔑 پاسخ‌نامه تشریحی تمرین‌های Git & GitHub

---

### 💡 پاسخ سوال ۱
این دستور یک «عکس/نسخه نهایی» از تمامی فایل‌های موجود در سبد آماده‌سازی (Staging) می‌گیرد و آن را در تاریخچه گیت ذخیره می‌کند.
* **نقش `-m`:** مخفف کلمه **Message** است و به گیت می‌گوید پیامی که درون کتیشن `"..."` نوشته شده را به عنوان توضیحاتِ این نسخه ذخیره کن.

---

### 💡 پاسخ سوال ۲
۱. **`git status`** : بررسی اینکه چه فایل‌هایی تغییر کرده‌اند.
۲. **`git add .`** : فرستادن تمام فایل‌های تغییریافته به سبد آماده‌سازی.
۳. **`git commit -m "توضیح تغییرات"`** : ثبت نهایی تغییرات در تاریخچه گیت.

---

### 💡 پاسخ سوال 4
از دستور git clone به همراه آدرس پروژه استفاده می‌کنیم:
git clone [https://github.com/user/project_name.git](https://github.com/user/project_name.git)


### 💡 پاسخ سوال 5
دلیل: گیت‌هاب برای ذخیره کدهای متنی (با حجم چند مگابایت) طراحی شده است، نه فایل‌های حجیم زیستی. آپلود فایل‌های چند گیگابایتی باعث کندی شدید گیت‌هاب می‌شود و محدودیت حجم گیت‌هاب (فایل‌های بالای ۱۰۰ مگابایت) خطا می‌دهد.

راه‌حل: ساخت فایلی به نام .gitignore در پوشه پروژه و نوشتن پسوند یا نام فایل‌های حجیم (مثلاً *.fastq) در داخل آن.
