# درس: پن‌ژنوم؛ کدام ژن‌ها در همه هست و کدام‌ها نه؟

**بخش:** `07_Bacterial_Genomics` · **ماژول:** `04_Comparative_Pan_Genome` · **پیش‌نیاز:** ماژول [آنوتیشن](../02_Genome_Annotation/)؛ [pandas](../../03_Python/06_Pandas/) · **زمان:** حدود ۶۰ دقیقه · **ابزار (از مستندات):** Panaroo (و Roary برای مقایسه) · **آخرین بازبینی:** 2026-10-21

## در یک نگاه

**در پایان این درس می‌توانید:**
1. پن‌ژنوم را به هسته، هسته‌ی نرم، پوسته و ابر تقسیم کنید.
2. بگویید چرا خطای آنوتیشن پن‌ژنوم را بزرگ‌تر از واقع نشان می‌دهد، و Panaroo چه می‌کند.
3. ‏Panaroo را با گزینه‌های درست اجرا کنید و خروجی‌هایش را بشناسید.
4. ماتریس بود و نبود ژن را با pandas بخوانید و ژن‌های ویژه‌ی یک گروه را پیدا کنید.

---

## ۱. داستان

چهل ایزوله‌ی *E. coli* از یک بیمارستان دارید؛ هر کدام آنوتیت‌شده (ماژول ۰۲). برخی به کارباپنم مقاوم‌اند و برخی نه. پرسش: **کدام ژن‌ها تنها در ایزوله‌های مقاوم‌اند؟** و پیش از آن: **این گونه چند ژن دارد؟** پاسخ دومی شگفت‌انگیز است: هر ژنوم *E. coli* کمابیش ۴۵۰۰ تا ۵۵۰۰ ژن دارد، ولی همه‌ی *E. coli*ها با هم ده‌ها هزار ژن گوناگون دارند. این مجموعه‌ی بزرگ **پن‌ژنوم** است.

---

## ۲. مفهوم به زبان ساده

### ۲.۱ هسته، پوسته، ابر

**خوشه‌ی ژنی**: یک «ژن» در پن‌ژنوم = همه‌ی نسخه‌های همانند آن در ژنوم‌های گوناگون. هر خوشه بر پایه‌ی **درصد ژنوم‌هایی** که آن را دارند دسته‌بندی می‌شود. فایل `summary_statistics.txt` (قالب Roary، که Panaroo هم می‌نویسد) این مرزها را دارد:

| دسته | در چند درصد ژنوم‌ها | چه ژن‌هایی |
| :--- | :--- | :--- |
| هسته (*core*) | ۹۹٪ تا ۱۰۰٪ | ژن‌های پایه‌ای: همانندسازی، ترجمه، متابولیسم مرکزی |
| هسته‌ی نرم (*soft core*) | ۹۵٪ تا ۹۹٪ | هسته‌ای که در چند ژنوم بی‌کیفیت گم شده |
| پوسته (*shell*) | ۱۵٪ تا ۹۵٪ | ژن‌های ویژه‌ی دودمان‌ها: آنتی‌ژن‌های سطحی، مسیرهای فرعی |
| ابر (*cloud*) | کمتر از ۱۵٪ | ژن‌های کمیاب: پلاسمیدها، پروفاژها، ژن‌های مقاومت تازه |

**پن‌ژنوم** = هسته + پوسته + ابر. **ژنوم جانبی** (*accessory*) = همه جز هسته.

### ۲.۲ پن‌ژنوم باز یا بسته

با افزودن هر ژنوم تازه، چند ژن تازه به پن‌ژنوم افزوده می‌شود؟
- **باز** (*E. coli*، *K. pneumoniae*): هر ژنوم تازه هنوز ژن تازه می‌آورد؛ پن‌ژنوم با شمار ژنوم‌ها بزرگ‌تر می‌شود.
- **بسته** (*Mycobacterium tuberculosis*، *Bacillus anthracis*): پس از چند ژنوم، کمابیش هیچ ژن تازه‌ای نمی‌آید.

### ۲.۳ چرا خطای آنوتیشن پن‌ژنوم را باد می‌کند

یک ژن که در یک ژنوم روی مرز دو کانتیگ **شکسته** است (ماژول ۰۱)، دو تکه می‌شود؛ ابزار ساده آن دو تکه را **دو ژن تازه** در ابر می‌شمارد. یک ژن که در یک ژنوم **پیش‌بینی نشده** (ماژول ۰۲: پروتئین‌های کوچک)، ژن هسته را به پوسته می‌برد. آلودگی، ژن‌های گونه‌ی دیگر را به ابر می‌افزاید. **نتیجه: ابر بزرگ‌تر و هسته کوچک‌تر از واقع.**

‏**Panaroo** خوشه‌ها را در یک **گراف** کنار هم می‌گذارد (همسایگی ژن‌ها روی ژنوم) و با آن خطاها را درست می‌کند: تکه‌های یک ژن را یکی می‌کند، ژن‌های گم‌شده را در همسایگی ژن‌های کناری **دوباره می‌جوید** (*refinding*)، و خوشه‌های کمیابی را که با همسایه‌هایشان نمی‌خوانند (آلودگی محتمل) برمی‌دارد.

## ۳. گام ۱: اجرای Panaroo (از مستندات)

ورودی: فایل‌های GFF3 همه‌ی ژنوم‌ها، **با توالی** (همان خروجی Prokka یا Bakta). به گفته‌ی مستندات Panaroo:

<div dir="ltr">

```bash
mkdir results
panaroo -i *.gff -o results --clean-mode strict
```

</div>

| بخش | چیست |
| :--- | :--- |
| ① `-i *.gff` | فایل‌های GFF3 همه‌ی ژنوم‌ها (Prokka یا Bakta؛ GenBank هم پذیرفته می‌شود) |
| ② `-o results` | پوشه‌ی خروجی |
| ③ `--clean-mode strict` | **اجباری**: `strict`، `moderate` یا `sensitive` |

به گفته‌ی مستندات، حالت `strict` (سخت‌گیرترین) برای بیشتر کارها **منابع آلودگی و خطا را برمی‌دارد و بیشتر ژن‌های مورد علاقه را نگه می‌دارد**. اما **پلاسمیدهای بسیار کمیاب** از آلودگی جداشدنی نیستند؛ اگر نگه داشتن آن‌ها مهم است (به بهای آلودگی بیشتر)، `--clean-mode sensitive`.

با هم‌ترازی ژن‌های هسته (برای فیلوژنی، بخش ۰۸):

<div dir="ltr">

```bash
panaroo -i *.gff -o results --clean-mode strict -a core --aligner mafft --core_threshold 0.98 -t 8
```

</div>

| گزینه | کار | پیش‌فرض |
| :--- | :--- | :--- |
| ‏`-a core` / `-a pan` | هم‌ترازی ژن‌های هسته / همه‌ی خوشه‌ها | بی هم‌ترازی |
| ‏`--aligner` | ‏`mafft`، `clustal`، `prank` یا `none` | ‏mafft |
| ‏`--core_threshold` | سهم ژنوم‌هایی که یک ژن باید داشته باشد تا «هسته» در هم‌ترازی شمرده شود | 0.95 |
| ‏`-t` | هسته‌های پردازنده | 1 |
| ‏`--remove-invalid-genes` | آنوتیشن‌های ناجور (طول نادرست، کدون پایان زودرس) را نادیده بگیر؛ برای GFFهای RefSeq | خاموش (Panaroo با خطا می‌ایستد) |

**پیش از Panaroo:** همه‌ی ژنوم‌ها را با **یک ابزار و یک نسخه‌ی پایگاه** آنوتیت کنید (ماژول ۰۲، اشتباه رایج ۳). مستندات Panaroo یک گام کیفیت هم دارد (`panaroo-qc` با پایگاه Mash) تا ژنوم‌های آلوده یا از گونه‌ی دیگر را پیش از کار پیدا کنید.

## ۵. گام ۳: خواندن ماتریس با pandas

یک ماتریس `.Rtab` کوچک **فرضی** (۶ خوشه، ۴ ژنوم؛ دو ژنوم آخر مقاوم):

<div dir="ltr">

```text
Gene	isoA	isoB	isoR1	isoR2
dnaA	1	1	1	1
gyrA	1	1	1	1
fimH	1	1	0	1
group_101	1	0	0	0
blaKPC	0	0	1	1
group_207	0	0	1	1
```

</div>

<div dir="ltr">

```python
# pangenome_table.py: categories and resistant-only genes from a Panaroo .Rtab file
import pandas as pd

pa = pd.read_csv("gene_presence_absence.Rtab", sep="\t", index_col=0)   # ①
n = pa.shape[1]                                                          # ②
freq = pa.sum(axis=1) / n                                                # ③
print(freq)

resistant = ["isoR1", "isoR2"]
others = [c for c in pa.columns if c not in resistant]
only_res = pa[(pa[resistant].sum(axis=1) == len(resistant)) & (pa[others].sum(axis=1) == 0)]   # ④
print(list(only_res.index))
```

</div>

| نشانه | کار |
| :---: | :--- |
| ① | ‏`index_col=0`: ستون نخست (نام ژن) برچسب سطرها شود (بخش ۰۳، ماژول ۰۶) |
| ② | ‏`shape[1]` = شمار ستون‌ها = شمار ژنوم‌ها |
| ③ | ‏`sum(axis=1)`: جمع هر **سطر** = شمار ژنوم‌هایی که ژن را دارند |
| ④ | ژن‌هایی که در **همه‌ی** مقاوم‌ها هستند و در **هیچ** غیرمقاومی نیستند |

با دست: فراوانی‌ها `dnaA` و `gyrA` ‏1.0 (هسته)، `fimH` ‏0.75 (پوسته)، `group_101` ‏0.25، `blaKPC` و `group_207` ‏0.5 (پوسته). ژن‌های ویژه‌ی مقاوم‌ها: **`blaKPC` و `group_207`**.

‏`group_207` چیست؟ خوشه‌ای بی‌نام که همیشه همراه `blaKPC` است: شاید بخشی از همان پلاسمید یا ترانسپوزون (Tn4401). **همراهی ≠ علیت**: ژن‌هایی که روی یک پلاسمید هستند همه با هم «ویژه‌ی مقاوم‌ها» دیده می‌شوند؛ برای جدا کردن، به جای آن‌ها روی کانتیگ و به فیلوژنی (همبستگی دودمانی) نگاه کنید.

## ۶. سه اشتباه رایج

**۱. آنوتیشن ایزوله‌ها با ابزارها یا نسخه‌های گوناگون.** نام‌ها و مرزهای ژن فرق می‌کنند و ابر بزرگ می‌شود. یک ابزار، یک نسخه، یک پایگاه.

**۲. اسمبلی‌های بی‌کیفیت یا آلوده در ورودی.** هر اسمبلی تکه‌تکه، ژن‌های هسته را می‌شکند؛ هر اسمبلی آلوده، ژن‌های گونه‌ی دیگر را به ابر می‌افزاید. پیش از پن‌ژنوم، معیار پذیرش ماژول ۰۱ و `panaroo-qc`.

**۳. سنجیدن اندازه‌ی پن‌ژنوم دو گونه با منحنی انباشت.** به گفته‌ی مستندات Panaroo، منحنی‌های انباشت رابطه‌ی تبارزایشی ایزوله‌ها را در نظر نمی‌گیرند و برای سنجیدن داده‌های گوناگون نامناسب‌اند؛ مستندات بسته‌ی R به نام **panstripe** را پیشنهاد می‌کند.

## 📘 برای کنجکاوها

- ‏**‏Roary:** ابزار قدیمی‌تر و سریع پن‌ژنوم؛ همان قالب خروجی، ولی به خطاهای اسمبلی بسیار حساس‌تر. Panaroo برای درست کردن همین خطاها ساخته شد.
- **پلاسمیدها در پن‌ژنوم:** چون Panaroo هر ژن را با همسایه‌هایش می‌سنجد، ژن‌های یک پلاسمید کمیاب شاید در حالت `strict` برداشته شوند؛ برای پرسش‌های پلاسمید، `sensitive` یا ابزار ویژه (MOB-suite، بخش ۰۸).
- ‏**‏GWAS باکتریایی:** ابزارهایی مانند Scoary و pyseer ژن‌های پوسته و ابر را با یک فنوتیپ (مقاومت) می‌سنجند و ساختار جمعیت را در نظر می‌گیرند.

## جمع‌بندی

- پن‌ژنوم = هسته (≥ ۹۹٪) + هسته‌ی نرم + پوسته + ابر (< ۱۵٪).
- خطای آنوتیشن و اسمبلی، ابر را باد و هسته را کوچک می‌کند؛ Panaroo با گراف، تکه‌ها را یکی می‌کند، ژن‌های گمشده را دوباره می‌جوید و آلودگی را برمی‌دارد.
- ‏`panaroo -i *.gff -o results --clean-mode strict [-a core]`؛ برای فیلوژنی، `core_gene_alignment_filtered.aln`.
- ‏`.Rtab` با pandas: فراوانی هر ژن، و ژن‌های ویژه‌ی یک گروه؛ همراهی را علیت نخوانید.

## واژه‌نامه‌ی درس

| واژه | معنی |
| :--- | :--- |
| پن‌ژنوم | همه‌ی ژن‌های یک گروه ژنوم، روی هم |
| ژنوم هسته / جانبی | ژن‌های همه (یا کمابیش همه) / بقیه |
| پوسته / ابر | ژن‌های میانه‌فراوان / کمیاب |
| خوشه‌ی ژنی | نسخه‌های همانند یک ژن در ژنوم‌های گوناگون |
| پن‌ژنوم باز / بسته | با افزودن ژنوم، ژن تازه می‌آید / نمی‌آید |
| ‏refinding | جست‌وجوی دوباره‌ی ژن گمشده در همسایگی ژن‌های کناری |
